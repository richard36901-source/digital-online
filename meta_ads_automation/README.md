# אוטומציית ניהול קמפיינים - Meta Ads

סקריפט Python שרץ פעם ביום, בודק את חשבונות המודעות של רחל, טל וגל, ומבצע אוטומטית:
- השהיית מודעות עם ROAS מתחת ל-1.5 (או הוצאה בלי תוצאות כשאין נתוני ROAS)
- - רוטציית קריאטיב + קופי למודעות שרצות 3+ ימים
  - - רישום כל החלטה ופעולה ללוג (`logs/automation_log.jsonl`)
    - - עדכון דשבורד **god_manager.html** - מציג את נתוני כל הקמפיינים (הוצאה, לידים, עלות
      -   לליד, ROAS, סטטוס) בכל 4 החשבונות המנוהלים (רחל, טל, גל + החשבון האישי שלך) במקום
      -     אחד. קריאה-בלבד, לא נוגע בשום מודעה או קמפיין.
     
      - **הכל רץ אוטומטית ללא אישור בזמן אמת** - זו הסיבה שקריטי להריץ קודם במצב `DRY_RUN` (ראו למטה).
     
      - ## למה זה רץ אצלך ולא אצל Claude?
     
      - הסביבה שבה Claude מריץ קוד חסומה מגישה ל-graph.facebook.com. הסקריפט צריך לרוץ על
      - מחשב/שרת שיש לו גישה רגילה לאינטרנט - המחשב שלך, VPS, או שירות כמו PythonAnywhere.
     
      - ## התקנה
     
      - ```bash
        cd meta_ads_automation
        python3 -m venv venv
        source venv/bin/activate   # ב-Windows: venv\Scripts\activate
        pip install -r requirements.txt
        ```

        ## הגדרה (חובה לפני הרצה ראשונה)

        1. **הטוקן** - פתח את `meta_api_credentials.txt` (נמצא בתיקייה שמעל) והעתק את ה-Access Token.
        2.    מומלץ להגדיר אותו כמשתנה סביבה ולא לשים אותו בקוד:
        3.   ```bash
                export META_ACCESS_TOKEN="הטוקן_שלך_כאן"
                ```

             2. **page_id** - כבר הושלם ב-`config.py` (`PAGE_IDS`), נשלף אוטומטית מתוך מודעות
             3.    קיימות בכל חשבון. אם דף הפייסבוק של לקוח משתנה בעתיד, יש לעדכן שם.
          
             4.3. **ספריית קריאטיבים** - צור מבנה תיקיות תחת `creative_bank/`:
                ```
                   creative_bank/
                     רחל/
                       images/          # קבצי jpg/png
                       copy.json        # [{"message": "...", "headline": "...", "link": "..."}]
                     טל/
                       images/
                       copy.json
                     גל/
                       images/
                       copy.json
                   ```
                   אם הקריאטיבים מגיעים מגוגל דרייב - הכי פשוט להתקין Google Drive Desktop, לסנכרן
                   את התיקייה של הלקוח מקומית, ולהצביע (או להעתיק קבצים) לתוך `creative_bank/<לקוח>/images/`.

                4. **בדוק את config.py** - ודא שהספים (`ROAS_THRESHOLD`, `CREATIVE_ROTATION_DAYS`) מתאימים לך.

                ## הרצה ראשונה - חובה במצב DRY RUN

                ב-`config.py`, `DRY_RUN = True` הוא ברירת המחדל. במצב הזה הסקריפט **לא מבצע שום
                שינוי אמיתי** בחשבונות - הוא רק מדפיס ורושם ללוג מה הוא *היה* עושה.

                ```bash
                python main.py
                ```

                עברו על הלוג (`logs/automation_log.jsonl`) ווודאו שההחלטות הגיוניות - האם המודעות
             שסומנו כ"לא רווחיות" באמת כאלה, האם הרוטציה בוחרת קריאטיבים נכונים וכו'.

             בסוף כל הרצה (גם ב-DRY RUN) נוצר/מתעדכן קובץ `god_manager.html` בתיקיית
             `meta_ads_automation`. פתחו אותו בדפדפן כדי לראות דשבורד עם כל הקמפיינים בכל
             4 החשבונות - הוצאה, לידים, עלות לליד, ROAS וסטטוס, עם סינון לפי לקוח.

             **רק אחרי שבדקתם ואתם בטוחים** - שנו ב-`config.py`:
             ```python
             DRY_RUN = False
             ```

             ## הרצת הדשבורד בלבד (god_manager)

             אפשר לרענן רק את הדשבורד, בלי להריץ את כל בדיקת ה-ROAS/רוטציה:

             ```bash
             python dashboard.py
             ```

             זה קריאה-בלבד מול ה-API (לא משהה ולא מחליף כלום) - בטוח להריץ בכל זמן, גם כמה
             פעמים ביום אם רוצים תמונת מצב עדכנית יותר. אפשר גם להוסיף לזה שורת cron נפרדת
             בתדירות גבוהה יותר מהאוטומציה הראשית, למשל כל שעה.

             ## הרצה אוטומטית יומית (cron)

             בלינוקס/מק, ערכו crontab:
             ```bash
             crontab -e
             ```
             והוסיפו שורה (דוגמה - הרצה כל יום ב-8:00 בבוקר):
             ```
             0 8 * * * cd /path/to/meta_ads_automation && /path/to/venv/bin/python main.py >> logs/cron.log 2>&1
             ```

             ב-Windows - השתמשו ב-Task Scheduler ליצירת משימה יומית שמריצה:
             ```
             venv\Scripts\python.exe C:\path\to\meta_ads_automation\main.py
             ```

             ## מבנה הקבצים

             - `config.py` - כל ההגדרות (טוקן, חשבונות, ספים)
             - - `insights.py` - משיכת נתוני ביצועים מה-API (ברמת מודעה, לצורך ההשהיה/רוטציה)
               - - `rules.py` - מנוע הכללים (מי להשהות / למי לרענן קריאטיב)
                 - - `actions.py` - הפעולות בפועל מול ה-API (השהיה, יצירת קריאטיב, החלפה)
                   - - `creative_rotation.py` - בחירת הקריאטיב/קופי הבא בתור מהבנק
                     - - `dashboard.py` - בונה את **god_manager.html** (ברמת קמפיין, לכל 4 החשבונות, קריאה-בלבד)
                       - - `logger.py` - רישום ללוג
                         - - `main.py` - מריץ הכל יחד, פעם אחת (להריץ דרך cron כל יום)
                           - - `rotation_state.json` - נוצר אוטומטית, זוכר איזה קריאטיב שימש אחרון לכל מודעה
                             - - `god_manager.html` - נוצר אוטומטית בכל הרצה - הדשבורד עצמו, פותחים בדפדפן
                              
                               - ## אזהרות חשובות
                              
                               - - **אין אישור בזמן אמת** - ברגע ש-`DRY_RUN=False`, הסקריפט משהה מודעות ומחליף
                                 -   קריאטיבים באופן עצמאי לגמרי, על כסף אמיתי של לקוחות. בדקו היטב לפני שמכבים DRY_RUN.
                                 -   - **הטוקן לא פג תוקף** - נוצר עם "אף פעם" (Never expire) כדי שהאוטומציה לא תישבר.
                                     -   משמעות הדבר שהוא תקף לצמיתות עד שתבטלו אותו ידנית ב-Business Settings - שמרו עליו
                                     -     במקום מאובטח (לא ב-git, לא בצ'אט).
                                     - - **ROAS דורש מעקב המרות תקין** - אם לחשבון אין Pixel/Conversions API מוגדר כראוי,
                                       Meta לא תחזיר `purchase_roas` והסקריפט יפעל לפי כלל הגיבוי (הוצאה בלי תוצאות).
